根因定位

错误类型为 TypeError: Cannot read property 'map' of undefined，触发点在 UserList.jsx 第 28 行。

问题根因是 users 参数未做空值保护。当父组件在数据加载完成前渲染 UserList，或接口返回异常导致 users 为 undefined/null 时，直接调用 users.map() 会抛出 TypeError，导致整个组件崩溃白屏。

触发条件：

  • 父组件初始状态 users 为 undefined，未传参
  • 接口请求失败或返回格式异常，data.users 字段缺失
  • 后端返回 { users: null } 而非空数组
修复方案（防御式处理）
UserList.jsx — 修复后
function UserList({ users }) { // 添加默认值 + 空值保护 const safeUsers = users ?? []; return ( <div> {safeUsers.length > 0 ? safeUsers.map(u => <span key={u.id}>{u.name}</span>) : <span style={{ color: '#999' }}>暂无数据</span>} </div> ); }
修改说明：使用空值合并运算符 ?? 将 null/undefined 统一转为空数组 []，确保 .map() 调用安全。同时增加空状态展示，提升用户体验。
改动量：新增 1 行默认值处理 + 三元表达式替换原 map 调用，属于最小改动。
影响范围评估
影响文件仅 UserList.jsx
影响逻辑仅组件渲染层，不影响数据获取和状态管理
向后兼容完全兼容，原有正常传入数组的行为不变
副作用风险无

修复结论

总体评价

该 Bug 属于空指针/空值未防护类问题，在前端开发中高频出现。本次采用防御式处理策略，通过默认值兜底确保组件健壮性。修复后可安全合入主分支，建议同步补充上述回归测试用例到 CI 流水线。

后续建议

• 排查项目中其他使用 .map()/.filter() 等数组方法的位置，统一添加空值保护
• 在父组件层面对接口返回数据做标准化处理（null → []），从源头避免此类问题
• 考虑引入 TypeScript 严格模式，在编译阶段拦截部分空值问题
